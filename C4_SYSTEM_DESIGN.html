1Level 1 — System Context

The platform sits between a sales team that has to defend numbers in a meeting and a dataset that never observed the thing everyone wants to buy. There is no footfall counter on any screen in the network; audience is inferred, and the system's job is to make every inferred number traceable back to a column.

One external constraint shapes the whole design. Both the Azure endpoint and the repo require the company network (office Wi-Fi or VPN); off-network the API returns 403, which is not a bad key. Every LLM-touching path therefore has a deterministic fallback, and no deliverable is unrunnable without a key.

3Level 3 — Components

Four containers are worth opening: the orchestrator because it holds the judgement, D3 and D4 because they hold the maths, and D1/D2 + the gateway because that is where language meets arithmetic.

3.1  D5 — Agentic Orchestrator

D5's premise is that four engines that each work in isolation still produce a confident wrong answer at the joins. Every component below exists because a specific join failed on a real brief.

3.1b  The agent loop — how D5 decides, and how we audit it

Everything above is a pipeline: given a brief, it produces one plan. What makes D5 an agent is what happens next — it inspects the plan it just built, decides whether it can do better, changes one thing, and measures. The loop is bounded by construction, because an unbounded loop against a metered API is a cost incident waiting to happen.

LeverWhat it changesOffered only when
grow_shortlist Offers the optimiser up to 3× more candidates than the sizing heuristic chose Inventory was actually withheld. This is the only lever that can improve on a proven optimum, because it is the only one that expands the feasible set — deleting options can never beat an exact solve.
raise_supplementary_share Allows more secondary-priority inventory into the plan The brief's inventory is split into priority tiers
drop_staging Releases inventory that was being held back in stages The plan was staged
shrink_shortlist Tightens the candidate set Greedy solves only. Against a CP-SAT optimum it is provably incapable of helping, so offering it would waste an iteration.

Measured honestly. Across the six real briefs the loop improves three of them and is correctly inert on the other three. The largest single gain in the system was not the agent's at all — it was fixing the shortlist to order by audience-pool diversity for reach objectives and by value for frequency objectives, which is worth +144% on campaign 1. We report it that way round because the alternative is crediting the agent for a bug fix.

4Runtime view — brief to plan

One request, end to end. The two decision diamonds are the interesting part: this is a pipeline that is allowed to stop.

  2. UI → AD orchestrate(brief, constraints)
  3. AD → D5 Orchestrator.plan(...)
  4. D5 → D2 parse_brief — regex, deterministic, zero cost
  5. D5 → LLM read_brief (nano, cache checked first) → structured fields + evidence quotes

Branch — market not resolvable

Branch — resolved, continue

  2. D5 shortlist_size, budget_verdict, infer_industry → build_cohort

Branch — cheapest line still unaffordable
Return Refusal(BUDGET_UNUSABLE) with the funnel counts, so the rep can see it was an affordability wall and not an inventory wall.
Branch — affordable, solve
  1. D5 → D4 allocate on the primary-inventory budget (70%)
  2. D5 → D4 allocate on the supplementary budget (30% cap)
  3. D5 _rededupe_reach across both solves — each audience pool counted once, not twice
  4. D5 → LLM narrative_facts then review_plan (mini) → prose + unmet-ask critique
  5. D5 → AD Plan: lines, KPIs, and explain_line derivation per line
  1. AD → UI JSON-safe dicts only — no engine types cross the seam
  2. UI → Rep plan table, evidence drill-down, exportable proposal
Every branch that ends in a refusal is a designed output, not an error path. A brief with an INR budget and no FX rate anywhere in the data is refused, because guessing a rate and quoting from it is worse than stopping. A brief naming a city the network does not serve is refused with the three real markets listed. Both were real out-of-sample failures before diagnose() existed — two of three rephrased briefs crashed outright and the third was confidently wrong.

6Cross-cutting concerns

6.1  The determinism boundary

The single most important architectural line in the system. It is enforced by the fact that llm_agent.py is the only module holding an Azure client, so the boundary is visible in the import graph rather than being a convention.

The model mayThe model may not
Read free text into a closed, enumerated vocabulary Produce a price, a score, a slot count or a reach figure
Name an audience archetype from computed facts, behind a guardrail Choose which screens are in the plan
Write the rep-facing narrative from a computed fact dict Introduce a number that is not already in that dict
Critique the plan for unmet asks in the brief Silently repair a gap by substituting a proxy nobody agreed to

The consequence is the property the demo rests on: "why is this screen 60.97?" is answerable from columns. Remove the API key entirely and the system still plans, still prices, still allocates and still explains — it loses fluency, not capability.

6.2  The explainability contract

Provenance columns are carried untouched from D3 and D1, through both solvers, onto the selected rows. A worked line from campaign 6:

LabelDerivation shown to the rep
What it costs60.97 per slot per day × 1 slot a day × 25 days = 1,524
The price range59.71 cheapest / 60.99 typical / 62.16 highest — quoted right at the typical price; attributed to this screen's own sales, or to comparable screens when it has none
Where it's fromthis screen's own past bookings, adjusted by our trained price model because there are only a few of them
Chance they say yes93%, from how often real deals at this price relative to the typical price were actually lost on price
Who walks past9,668 people on an average day, in this time block
How they see it25 seconds of dwell; all 6 slots loop once a minute, so each person sees the loop ~0.4 times and 38% of them look. We own 1 of 6 slots → ~0.16 views per passer-by
Impressions9,668 × 0.16 = 1,541 views a day, 38,519 over 25 days
Distinct people1,424 a day — fewer than the views, because 1.1 views is still one person. Also why a 6th slot is worth less than a 1st slot elsewhere
The derivation surfaced an insight the numbers alone hid. At one slot on a 25-second-dwell screen only ~16% of passers-by see the ad, and impressions ÷ reach is 1.08 — so this plan is buying reach, not frequency. That is a strategy statement a rep can defend, and it was invisible until the arithmetic was written out.

6.4  Refusal semantics

Five refusal states, each naming the first funnel stage that emptied, because the remedies are opposites: MARKET_UNRESOLVED, DAYPART_UNMEASURABLE, NO_RELEVANT_INVENTORY, NO_CAPACITY, BUDGET_UNUSABLE. Warnings are split into client_facing_warnings and internal_warnings so a rep never reads a model diagnostic aloud in a meeting.

6.5  Disclosure semantics — the third state, between doing and refusing

Refusing and delivering are not the only two outcomes, and an adversarial review of 14 briefs found this system's real weakness was neither: it was silence. Three cases where it neither did the thing nor said it could not.

CaseWhat it used to doWhat it does now
A regulated advertiser category
gambling, alcohol, vaping, high-cost credit, and six more		 Priced and optimised it like any other brief. industry_vertical existed as a column on the leads table and was never consulted. Three disclosures: the category, its pairing with campus / school / under-21 language, and that pricing confidence is low — the rate card is built from what this network charged for inventory, never from what it charged this kind of advertiser, so a category with no historical analog has no evidence behind its band. Nothing is blocked. We hold no policy data, and a platform that silently refuses business it was not asked to adjudicate is as wrong as one that silently prices it.
A market we do not sell in
"Las Hackland and Port Meridian"		 Resolved Las Hackland, dropped Port Meridian without a word. resolve_market answers "which one market is this brief about" — correct for planning, wrong for disclosure. Names the unsupported place on the plan. The client would otherwise have received coverage of half what they asked for, with nothing admitting so — the exact failure mode this design claims to have eliminated.
The price we decline to raise The 2,000-resample bootstrap of the demand elasticity was committed as a PNG and a JSON that nothing in the product ever opened. On the pricing screen with its interval and its four caveats. This matters more than an ordinary chart because the finding is a negative result: unevidenced, "we do not recommend charging more" sounds like a system that found nothing; with the interval shown it is a measurement.

Deterministic floor, model for generalisation. The category and proximity patterns are word lists: always correct, no network, so neither capability depends on an API being reachable. The model exists only for what a list cannot enumerate — "iGaming", "sportsbook", "Port Meridian" — which is the out-of-sample case a fixed list fails at. One nano call per brief carries both, cached and fenced. The determinism boundary is unchanged: the model returns labels from a closed vocabulary plus place names, and deterministic code decides what they mean. It cannot price, score or exclude anything. It can only cause a sentence to be written.

False positives are the real risk here, not misses. A regulated-category warning stapled to every honest plan is worse than no warning at all, and the first version of these patterns did exactly that twice: bare slots matched all six real briefs, because six rotation slots per time block is this domain's own vocabulary; and a bare 16-21 range matched the literal dim_slot label "16-20 Evening", every budget ending in those digits, and most date fragments. Hence slot machine, and age ranges that require an age noun. Most of the 15 acceptance checks guarding this are false-positive checks rather than capability checks, which is the ratio the risk actually has.

7Key design decisions

Nine decisions where the alternative was tried, measured and rejected. Each was verified against the data rather than argued from taste.

#DecisionRejected alternativeMeasured consequence
1Model the reach curve as a min of tangent lines, including the λ=0 tangentTangents at positive λ onlyEvery positive-λ tangent has a positive intercept, so the solver banked reach for buying nothing — up to 69% of a pool at high λ. Objective was inflated 33%; correcting it moved real reach +5.3%.
2Deduplicate reach by pool_idSum people across selected screens~25× overcount. Two screens in one station counted the same commuter twice.
3Fit the win model inside lost leads (price-driven vs. not)Bookings vs. leadsBookings are 99.7% wins by construction — unidentified. Before the fix, 100% of quotes sat at the cap; after, 0.02%, with 99.96% at an interior optimum.
4Two bounds on the win fit: base ratio and elasticityEither bound aloneA base ratio of 12.75 fails the location bound but passes the steepness bound; an elasticity of 573 does the reverse. One bound admits a degenerate fit.
5Blend GBM and empirical price by booking credibility, floored at 0.50, with the band rescaled and the floor clamped to the peer minimumBlend the target onlyMoving the target and leaving the band put 69.5% of cells' target outside their own band and pinned 49.75% of quotes to the floor. With the clamp: floors below the network minimum went 1,308 → 0, minimum floor 1.52 → 13.93.
6Split the budget between primary and supplementary inventory (30% cap)Cap the supplementary shortlist sizeThe shortlist cap failed outright — 100% of spend stayed supplementary because 26 candidates was ~5× the fundable line count. The budget split holds: reach falls 30,423 → 24,244, which is the correct trade for putting 70% into the inventory the brief anchors on.
7An LLM intake agent in front of the regex, regex-first on conflictRegex onlyOn rephrased briefs the regex silently returned budget 0 and duration 0. Two of three out-of-sample briefs crashed; one was confidently wrong. After: one full plan ($4,455 of $4,500, reach 81,626), two correct refusals.
8Word-boundary cue matching with a two-hit minimumSubstring matchingSubstring matching found "mall" inside "small" and "vertical" inside the field label "Industry Vertical" — reporting two contradictory gaps on one brief.
9Disclose unsupported asks; never proxy themMap an unmatched ask to the nearest available categoryThe critic still flags "high-street retail corridors" on every campaign 6 run, correctly — there is no such POI type. A proxy nobody agreed to is worse than a stated gap.

8Deployment view

Cold-start sequence for a fresh clone

  1. git clone, then git config core.hooksPath .githooks — the hook is not active until this is run.
  2. cp .env.example .env and fill in the five values. Never paste the key into chat, a notebook, or a commit.
  3. python build_training_table.py → python encode_pricing_grain.py → retrain the model. Required only if the marts are stale; both are committed.
  4. python build_d1_audience_profiles.py to refresh the audience cube.
  5. python build_d5_orchestrator.py campaign_4.docx.parsed.txt — headless end-to-end check before touching the UI.
  6. streamlit run app.py. With no key or no engines, the façade serves stubs and the flow still demonstrates.

9Known limits and next steps

Stated here rather than discovered by a judge. Each of these is a decision with a reason, not an oversight.

LimitWhy it standsWhat fixing it would take
D3's recommended price is the target by construction The band is p10/p50/p90 of historical prices — median width 6.5% of target, revenue varying only 0.72% across it — and the win calibration pins the optimum to the target. Deriving the band from willingness-to-pay rather than realised prices. A redesign, not a tweak. Defensible today if described exactly this way.
No walking radius There are no coordinates in any of the 14 tables. "Same zone as the anchor POI" is the coarsest available proximity primitive. Coordinates. Documented as an assumption everywhere it is used.
day_type averaged out of the quote key Median weekday/weekend spread is 5.0%, p90 12.9% — real but second-order against the band width above. Carrying day_type through the quote key and the optimiser's cell identity.
Non-USD briefs are refused No FX rate exists anywhere in the data. Guessing one and quoting from it is worse than stopping. An explicit, stated rate in configuration — a disclosed assumption rather than an inference.
"High-street retail corridors" flagged as unmet on every run There is no high_street POI type. The critic is right, and a proxy nobody agreed to would be worse. Either a vocabulary entry mapped to a real POI type, or it stays a disclosure. Open decision.
Refreshed D1 not yet promoted It flips block 1 from a hard zero to a residual, which changes the brief-editor contract the UI is being built against. Deliberately deferred past the demo. Promoting it with the UI, together, after the demo.
D6 wiring incomplete Wire points 1, 6 and 7 remain; 2–5 are covered by the single orchestrate call, which is the intended path. Point adapters.usage() at llm_agent.usage() and drop the standalone Azure patch module — the gateway already owns that.
Backup demo. The stub-backed façade means the whole four-step flow runs with no key, no network and no engines. Recording that walkthrough now is the insurance policy against a 403 on demo day — and a 403 is a network condition, not something a working key can fix.
